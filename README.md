# 研译 PaperContext

**简体中文** | [English](README.en.md)

**为科研阅读而做，面向新手，开箱即用。**

**选好服务，填入 API Key，选中文字就能翻译。**

Context-aware paper translation in Zotero. Built for beginners: choose a provider, enter your API key, and start reading.

研译是一款面向科研论文阅读的 Zotero 划词翻译插件。选中文字，译文就在选区旁出现；必要时结合所在句、附近段落与当前论文的术语表，帮助理解专业表达，同时控制不必要的上下文和重复请求。

支持 **Zotero 10**。使用标准预设时，只需选择模型服务、填入自己的 **API Key**，无需手动填写接口地址或模型名。**不会编程也能用，无需终端命令、Python 环境、Node.js 或本地翻译服务器。**

> API Key 由你选中的模型平台提供，调用可能收费，账号需已开通对应模型。业务空间专用接口等少数情况可能需要补充设置，见[配置说明](docs/CONFIGURATION.md)。

## 先看这四点

- **新手友好**：下载安装包、选择服务、填 Key，就能开始；接口和默认模型已预填。
- **不打断阅读**：划词后译文就在选区旁，无需离开 PDF。
- **照顾论文语境**：结合受限上下文与论文术语表，遇到歧义可手动补充语境。
- **消耗看得见**：本地缓存、按需重译、Token 用量和 API 配置状态直接显示。

## 为什么做研译

阅读科研论文时，困难往往不只是遇到生词：

- **词懂了，意思却没对上。** 单独一个缩写可能有多种解释。例如 `LLM` 在人工智能论文里通常指大语言模型，脱离语境却可能被理解为另一种学位名称。
- **同一个术语，需要反复确认。** 一篇论文中的专有名词、方法名和缩写，需要在阅读过程中保持一致。
- **阅读节奏容易被打断。** 复制文字、切换窗口、粘贴、再返回原文，会打散对论证和方法的理解。
- **配置和环境维护占用精力。** 阅读辅助工具应该尽量做到填好 Key 后即可使用。
- **更多上下文也意味着更多消耗。** 每次发送大量正文并不总有必要，短句和已确认术语可以用更克制的方式处理。

研译围绕这些具体问题设计，不承诺消除误译，也不代替你对论文内容的判断。

## 功能

| 功能 | 阅读时如何使用 |
| --- | --- |
| 自动划词浮窗 | 选中文字、松开鼠标后，在选区旁直接查看中文译文 |
| 上下文翻译 | 根据选区长度，附带受限的所在句或附近段落 |
| 按需补充语境 | 译文有歧义时，点击“更多上下文重译”再补充附近文字 |
| 论文术语表 | 同一论文共享术语，其他论文互不影响 |
| 纠正术语 | 把 `LLM → 大语言模型` 等确认结果保存到当前论文 |
| 本地命中 | 再次单独选中已确认术语，或命中译文缓存时，不调用 API |
| 多模型提供商 | 六家官方接口预设，分别保存 Key、模型与验证记录 |
| 可见配置状态 | 显示当前提供商、模型、接口地址和上次验证结果 |
| 浮窗字号 | 用 A− / A＋ 调节译文大小，并记住选择 |
| Token 用量 | 显示服务返回的输入、输出及可用的缓存命中数据 |

## 三分钟上手：不用写代码

1. [下载 `papercontext-0.2.1.xpi`](https://github.com/Liuhuan3333/zotero-papercontext/raw/refs/heads/main/dist/papercontext-0.2.1.xpi)。在 GitHub 文件页中也可以点击下载原始文件。
2. 在 Zotero 中打开 **工具 → 插件 → 齿轮 → 从文件安装插件**，选择 XPI 文件。
3. 打开 **Zotero 设置 → 研译**，选择提供商，填写 API Key，点击“保存密钥”。
4. 点击“检查连接”，然后打开 PDF，选中需要理解的文字。

**不熟悉 API Key、安装入口或连接状态？** 请看[新手入门](docs/QUICKSTART.md)。

已有版本可直接覆盖安装，无需先卸载。插件保留既有配置、密钥和论文术语，不要求为了更新重新配置。

### 支持的服务

**DeepSeek、通义千问、智谱 GLM、Kimi、硅基流动、火山方舟。**

各家预填官方接口和默认模型，通常只需选择服务并输入 Key。你的账号仍需具有相应模型的权限；业务空间专用接口或特定接入点需要的额外参数，放在高级设置中。具体限制见 [配置说明](docs/CONFIGURATION.md)。

“已配置”表示 Key 已保存；“上次验证成功”带有历史时间，**不代表实时在线**。查看设置和切换服务不会触发后台连接测试。

## 一个术语纠正示例

在当前论文中选中 `LLM`，点击浮窗中的“纠正术语”，填写：

```text
原词：LLM
正确译法：大语言模型
```

保存后：

- 再次单独选中 `LLM`，直接使用本地确认的译法，不调用 API。
- 翻译包含 `LLM` 的句子时，将这条术语作为当前论文的约束交给模型。
- 其他论文不受影响，避免把一个领域的解释强加到另一篇论文。

如果当前选中的是整句，保存术语后可以点击“应用术语重译”。保存动作本身不会额外发送翻译请求。

## 如何控制消耗

默认只发送受限上下文：短词优先所在句，短句使用附近段落，长选区通常不再重复附加正文。只有你点击“更多上下文重译”，才扩大上下文范围。

本地译文缓存与服务端输入缓存是两回事：前者不需要调用 API；后者由提供商决定，仍可能收费。研译会保留适合复用的输入前缀，但**不通过填充文本、预热请求或发送整篇论文追求命中率**，也不承诺固定的命中率或省费比例。

浮窗显示的 Token 数来自 API 返回值；服务未提供时明确说明，不用估算值冒充真实用量。详见 [隐私与费用](docs/PRIVACY.md)。

## 数据与适用范围

- Key 保存在 Zotero 的登录凭据管理器，按提供商隔离，不写入普通偏好、译文缓存或安装包。
- 论文术语和有限数量的译文缓存仅保存在本机，不自动同步，不修改原始 PDF 或文献附件。
- 翻译时，选中文字、必要上下文、论文标题和相关术语会发送给你选中的模型提供商。
- 当前主要面向英语论文的中文辅助阅读，PDF 需要能够选中文字。
- 扫描件 OCR、整篇 PDF 翻译和排版还原不属于当前功能。
- 分栏、公式、跨页断句或 PDF 文本提取错误可能影响结果。重要概念与研究结论仍应对照原文确认。

## 开发与验证

无第三方 JavaScript 运行依赖。安装和阅读时不需要 Node.js；只有开发与构建需要 **Node.js 20+** 和系统 `zip` 命令。

```sh
npm test
npm run build
```

安装包和校验值输出到 `dist/`。模块说明和版本记录见 [开发说明](docs/DEVELOPMENT.md)。

目前已有核心策略、上下文限额、论文术语隔离、旧缓存兼容、多提供商参数和状态判断等自动测试。Zotero 集成曾在独立资料库中使用虚拟响应验证；这不等于每家真实 API 或每个账号都已验证可用。

欢迎提交 Bug 和改进建议。报告问题时请提供 Zotero 版本、插件版本、所选提供商/模型和复现步骤；**不要附上 API Key、完整凭据文件或包含私人内容的缓存文件。**
